The optional post-srst-float-ms property makes the PATA task-file and
alternate-status reads return FFh and ignores task-file writes for the
specified interval after SRST release. It defaults to zero. The 100 ms
value exercises delayed register availability. It is a fault injection,
not a measurement from the board. Linux also allows a settling interval
in ata_sff_wait_after_reset before examining status.

TRIM mode and trimnt (IDENT GitHub issue #2; 2026-11-09)

- QEMU 8.2, disks with discard=unmap on raw image files that were filled
  with random data before partitioning, so that every block of the image
  was allocated; one FAT16 partition each. Space given back by the
  emulated disk shows as a smaller allocation of the image file (du).
- Windows 2000 (w2k-hib, the four 1.3/1.8/3.3 release drivers): 200 MB
  disks on AHCI port 1 (AHCINT), the PIIX3 primary master (IDENT) and
  NVMe (NVMENT), a 256 MB SD card on sdhci-pci (MMCSDNT). trimnt D: to
  G: found each disk's adapter and address through
  IOCTL_SCSI_GET_ADDRESS ("D:\ is on Scsi0: path 0 target 1 lun 0",
  ...), switched TRIM mode on on that adapter only, filled 199 MB (SD:
  255 MB), "volume full", "trimmed 199 MB" (SD: 255 MB) from
  TRIM_STATUS. Image files: AHCI 204804 KB -> 3420 KB, IDE 204804 KB
  -> 8216 KB, NVMe 204800 KB -> 7416 KB. The SD image stayed allocated:
  QEMU 8.2's SD card model takes ERASE but neither changes nor discards
  the blocks. fsck.fat -n afterwards: no errors, no files left on any.

  10000 files of three sectors, every second one deleted (5000 holes of
  1.5 KB, plus 17 MB in one piece), on the PIIX3 secondary master

QEMU used for the tests
- QEMU 8.2.2 (-M pc: PIIX3 IDE in compatibility mode, 8086:7010,
  programming interface 80h; -M q35: no IDE function at all), patched
  (test environment only):
  - ATA disks with 1024/2048/4096-byte logical sectors (IDENTIFY words
    106/117-118) on the IDE bus.
  - The PIIX3 function reporting another device ID (ICH4 24CB) for the
    Intel timing-register path.
  - The CMD646 (1095:0646) PCI IDE controller built into the x86
    targets: native mode on both channels (programming interface 8Fh),
    one PCI INTA for both channels (level-sensitive, shared).
    SeaBIOS writes the legacy addresses 1F0h/3F4h/170h/374h into BAR 0-3
    of every native IDE function, which would make it decode the same
    ports as the PIIX3; with CMD646_BARS=e000 those writes are moved to
    E000h/E010h/E020h/E030h, as a BIOS that assigns free I/O space would
    do. Bus master (BAR 4) as SeaBIOS assigned it.
    CMD646_BARMASK=<hex>: only the BARs whose bit is set are moved
    (1 = BAR 0 ... 8 = BAR 3), the others stay on the legacy ports.
  - CMD646_STICKY=1: the CMD646 interrupt latches stay set until
    software writes 1 to them (CFR/ARTTIM23 in config space, MRDMODE
    bits 2/3 at bus master base + 1), and the PCI interrupt follows the
    latches, as on the real chips. Stock QEMU drops a latch when the
    drive drops INTRQ, which hides the problem.
  - CMD646_DEVID=0643/0648/0649[:rev]: the CMD646 model reports another
    member of the family (or revision).
  - IDE_PCI_DEVID=<vendor>:<device>[:<revision>]: the PIIX3 function
    reports another vendor/device (unknown controller, ALi M5229,
    RZ1000, CMD640, ServerWorks OSB4); its registers stay PIIX3's.
  - IDE_SIMPLEX=1: the bus master status reports bit 7 (simplex).
  - The SiI3112 model (1095:3112, class 0104, BAR 5 registers with
    SIEN) built into the x86 targets.
- QEMU's bus master is an SFF-8038i engine with PRDs; UDMA/MWDMA
  timing registers are accepted but have no effect on speed. The
  "modes" the driver reports (MWDMA 2 on PIIX3, UDMA 5 on ICH4) are
  what SET FEATURES and the timing registers were programmed to.
- Tools (sources in the tools folder of the work tree, not shipped):
  idetest (GET_INFO, SMART, pass-through, MODE SELECT, VERIFY,
  START STOP UNIT, power IOCTL), bench (QD32 4K write/read, 50 MB
  sequential verify by CRC), sumtool (CRC of a directory tree),
  secdump (sector dump), geom (geometry/capacity per drive), devstat
  (device node status, 2000/XP), hiio (64 KB write/read/compare at any
  offset of a raw disk, with a page-aligned buffer and with buffers
  2 and 6 bytes off a dword boundary).

  to 3, both saved values deleted, IDENT Start 4 (deleted at the next
  boot). With IDENT still a boot driver, removal first asks for

  Cancel leaves everything as it was (setup exit code 2).
- NT 3.1 load order: with the IDENT key given Tag 40 (as txtsetup.oem

  stopped with the system disk idle. The same with IRQ=0 DMA=0, and

  boot stops with 0x7B. A disk numbering matter of NT 3.1, described in

Several controllers in one machine (1.1)
QEMU's SeaBIOS writes 1F0h/3F4h/170h/374h into BAR 0-3 of every native
IDE function other than the PIIX3. The runs below leave them there (no
CMD646_BARS), or with CMD646_BARMASK leave one pair there and move the
other. QEMU then decodes the legacy ports for the CMD646, not for the
PIIX3: the situation of a machine booted from a native-mode controller
whose compatibility-mode drives are missing.
- Before (1.0 logic, debug build): NT 4.0 booted from the CMD646
  primary, k512 on the PIIX3 primary, CD + data1 on the PIIX3
  secondary: the PIIX3 channel at 1F0 reported 1 device (the CMD646's
  system disk), the one at 170 none, DMA errors and PIO for the system
  disk (the PIIX3's bus master moved its data), and the CMD646 itself
  was skipped as its ports were already taken: k512, the CD and data1

CD-ROM drives on NT 3.1, drive positions, shutdown (1.1 update)
Reported: on a VIA P4M800Pro-M board (VT8237 south bridge), the CD-ROM
drive on the primary master was missing in NT 3.1's File Manager.
- NT 3.1, system disk on AHCI, debug build, drive letters and CD-ROM
  root listing read with a new tool (drvlet): every layout found the
  drives and the CD-ROM was readable (7 entries in its root):
  CD primary master + data1 slave + data2 secondary master; CD alone
  on the primary master; data1 master + CD slave on the primary, a
  second CD master + data2 slave on the secondary (CdRom0 and CdRom1);
  CMD646 in native mode with a CD as primary master and one as
  secondary slave (both CdRom0/CdRom1, Fast Polling).
- The CD-ROM class driver scsicdrm set to Start 4 (as NT 3.1 leaves it
  without a SCSI adapter: NT 3.1 has no IDE CD-ROM support): no
  \Device\CdRom0 and no drive letter, the behaviour reported. Now the
  driver, having found an ATAPI device, sets it to 1 at boot ("scsicdrm,
  Start 4 -> 1"); the CD-ROM got its drive letter in the same boot and
  the next. With scsicdrm, cdfs and cdfs_rec all at 4: "scsicdrm, Start
  4 -> 1", "cdfs, Start 4 -> 1", CD readable; cdfs_rec left at 4.
- scsicdrm at 4, cdfs at 4 but cdfs_rec at 1 (the recognizer loads
  CDFS): only scsicdrm set to 1, cdfs left at 4, the CD readable.
- A side effect of the oemsetup.inf run below: it gives the IDENT key
  Tag 40, so IDENT loaded ahead of AHCINT and a data disk on the PIIX3
  became rdisk(0): autochk, then the boot stopped (the NT 3.1 disk

  that followed.
- oemsetup.inf on NT 3.1 (run through setup.exe -f -i with a wrapper
  INF calling InstallOption), no CD-ROM drive attached so the driver
